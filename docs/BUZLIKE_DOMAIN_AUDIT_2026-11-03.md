# ตรวจการย้ายโดเมน buzlike.com — 3 พฤศจิกายน 2026

**อัปเดตหลังแก้ไข:** ทั้ง 3 จุดด้านล่างแก้และตรวจบนเว็บจริงแล้ว: public indexing, metadata ของเดโม และ www redirect ดูผลส่งมอบใน `BUZLIKE_BRAND_DELIVERY_2026-11-03.md` เนื้อหาถัดไปเป็นผลตรวจตั้งต้นก่อนแก้

**ผล:** การใช้งานหลักที่ตรวจผ่าน 31 รายการ แต่การตั้งค่าเผยแพร่หลังย้ายโดเมนยังไม่ครบ 3 จุดด้านล่าง รอบนี้ไม่มีการแก้ไฟล์หรือการตั้งค่าบนโฮสต์

## จุดที่ต้องแก้

| ลำดับ | สิ่งที่พบจริง | ผลกระทบและวิธีแก้ |
| --- | --- | --- |
| 1 | หน้าแรกและหน้าสาธารณะยังมีทั้ง HTTP `X-Robots-Tag: noindex, follow` และ HTML `meta robots` เป็น `noindex, follow` | เป็นคำสั่งไม่ให้เก็บหน้าในดัชนีค้นหา ต้องปลดทั้งสองชั้นสำหรับหน้าสาธารณะ ส่วนหน้าเซ็นเอกสาร/จัดการ/พอร์ตัลที่ตั้งใจไม่ให้ค้นหาให้คง noindex |
| 2 | canonical, `og:url` และ `og:image` ของหน้าเดโม 9 หน้ายังชี้ไป `bisque-cormorant-534729.hostingersite.com` | ต้องแก้แหล่ง metadata ของหน้า PHP ให้ใช้ `https://buzlike.com` และตรวจทุกเส้นทางซ้ำ ไม่ใช่แก้เฉพาะหน้าแรก |
| 3 | `https://www.buzlike.com/` ตอบ 200 และคง URL www แยกจากโดเมนหลัก | ควรเลือกโดเมนหลักเดียวตาม URL ที่ใช้งานคือ `https://buzlike.com` แล้ว redirect www แบบถาวร โดยรักษา path/query |

หน้าแรกแก้ canonical และ Open Graph เป็น buzlike.com แล้ว ทั้ง `robots.txt` และ sitemap ก็ชี้โดเมนใหม่ถูกต้อง จึงไม่ได้จัดสองไฟล์นี้เป็นข้อผิดพลาด

## สิ่งที่ผ่านและหลักฐาน

- HTTPS ตรวจใบรับรองได้ปกติ ครอบคลุม buzlike.com และ www.buzlike.com; วันหมดอายุที่อ่านได้คือ 31 มกราคม 2027
- HTTP หน้าแรก redirect 301 ไป HTTPS
- หน้าแรก เมนูและ anchor ภายใน รูปเนื้อหา ตารางเปรียบเทียบ และฟอร์มสามขั้นใช้งานได้
- ราคาเลือกหนึ่งระบบเป็น 15,000–25,000 บาท และสองระบบเป็น 25,000–40,000 บาท; บังคับข้อมูลติดต่อ สร้างสรุป และประกอบเนื้อหาอีเมลตรงกับสรุป
- เปิดตรงครบ 9 เส้นทางเดโมได้ HTTP 200 และแสดง demo shell; refresh ของ WMS อยู่ถูกหน้า; หน้าไม่รู้จักตอบ HTTP 404
- ปุ่มขอใบเสนอราคาจาก CRM กลับโดเมนใหม่พร้อมเลือกระบบ CRM ถูกต้อง
- ไม่มี document overflow ที่ 375/390/768/1440 px; เมนูมือถือปิดเมื่อไปฟอร์ม
- ป๊อปอัป WMS กักโฟกัสและคืนโฟกัสได้ บาร์โค้ดอ่านกลับได้ `EL-001`
- ข้อมูลจองวันอนาคตบันทึกในเบราว์เซอร์ QR ตรงกับข้อมูล และ PDF บัตรออกหน้าเดียวพร้อม QR ที่อ่านกลับได้
- ไม่พบ JavaScript runtime error และไม่มี same-site POST จากการเตรียมสรุปใบเสนอราคา

หลักฐาน Chromium ผ่าน Playwright CLI อยู่ที่ `output/buzlike-audit-2026-11-03/`: `http-results.json`, `browser-results.json`, `decode-results.json`, ภาพ desktop/mobile และ `booking.pdf` ภาพและ PDF ถูกเปิดตรวจด้วย `view_image`

## ข้อจำกัด

- การตรวจนี้ยืนยันเฉพาะเส้นทางและ flow ที่ระบุ ไม่ใช่การรับรองทุกฟังก์ชัน ทุกเบราว์เซอร์ หรือ performance/Core Web Vitals
- การจองและข้อมูลเดโมอยู่ใน browser-local storage; ไม่ได้ย้ายหรือทดสอบฐานข้อมูลกลาง
- ฟอร์มใบเสนอราคาสร้างข้อความให้ผู้ใช้ส่งเอง ไม่ได้ส่ง LINE/อีเมลหรือชำระเงินจริง
- เดโมร้านค้าภายนอกตรวจการเปิดหน้าเชื่อมเท่านั้น ไม่ได้รับรอง checkout ของผู้ให้บริการภายนอก พบ request prefetch ของเว็บไซต์ภายนอกที่ถูกยกเลิกเมื่อเปลี่ยนหน้า ไม่ได้ตีความเป็นข้อผิดพลาดของระบบนี้
- การเข้าครั้งแรกพบ Hostinger browser check ชั่วคราว จากนั้นเปิดเว็บได้ตาม flow ปกติโดยไม่มีการข้ามระบบตรวจสอบ หน้า challenge เคยร้องขอ favicon.ico แล้วได้ 404; favicon ที่เว็บกำหนดใช้ SVG จึงไม่ได้สรุปว่า favicon ของเว็บเสียจากเหตุการณ์นั้น
- ไม่ได้ตรวจ Search Console หรือสถานะ index จริงของ Google ข้อ noindex ข้างต้นเป็นผลอ่าน directive จาก HTTP/HTML ปัจจุบัน
