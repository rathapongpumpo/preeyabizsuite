# แผนเพิ่มดอกเตอร์ลอว์เยอร์ในศูนย์รวมผลิตภัณฑ์

วิเคราะห์และจำลองวันที่ 15 พฤศจิกายน 2026 — ต่อมาผู้ใช้ให้เพิ่มดอกเตอร์ลอว์เยอร์ก่อน จึงเผยแพร่เฉพาะการ์ดบนเว็บหลักแล้ว รายละเอียดอยู่ใน `LAWYER_PRODUCT_DELIVERY_2026-11-15.md` ส่วนการรวบรวมระบบอื่นและการเพิ่มลิงก์กลับภายในแอปกฎหมายยังเป็นแผนงานถัดไป

## ข้อสรุป

เพิ่ม **ดอกเตอร์ลอว์เยอร์ (Doctor Lawyer)** เข้าในศูนย์รวมผลิตภัณฑ์ `https://buzlike.com/#products` และเชื่อมไปยัง `https://lawyer.buzlike.com/` ในแท็บใหม่ ไม่ต้องเพิ่มเมนูบนหัวเว็บอีก ศูนย์รวมนี้ต้องครอบคลุมระบบของ BUZLIKE ทั้งหมดที่นำเสนอได้ ไม่จำกัดเฉพาะ POS และระบบกฎหมาย

คำว่า “ผลิตภัณฑ์ตัวที่สอง” ในข้อเสนอเดิมหมายถึงรายการถัดจาก POS ที่ลงในส่วนนี้ไว้แล้ว ไม่ใช่จำนวนผลิตภัณฑ์ทั้งหมดของผู้ใช้ จึงแก้ถ้อยคำและขอบเขตให้ชัดเจนตามคำทักท้วงของผู้ใช้

## ขอบเขตศูนย์รวมที่ต้องรวบรวม

- ระบบที่เปิดให้เข้าถึงได้แยกต่างหาก: BUZLIKE POS และดอกเตอร์ลอว์เยอร์ โดยแสดงเงื่อนไขการทดลองของแต่ละระบบตามจริง
- ระบบที่มีต้นแบบภายในเว็บหลัก: คลังสินค้า งานขาย/CRM พร้อมขั้นตอนสัญญาและลงนาม และระบบขนส่ง สามารถนำเสนอเป็นระบบที่รับปรับพัฒนาต่อ โดยไม่กล่าวว่าพร้อมใช้งานจริงเท่ากันทุกตัว
- SmartPOS ในเดโมและ BUZLIKE POS ต้องตรวจความสัมพันธ์ก่อนนับเป็นคนละผลิตภัณฑ์ ส่วนการลงนามอาจเป็นโมดูลของชุดงานขาย ไม่ควรนับจำนวนเพิ่มอัตโนมัติ
- พบโฟลเดอร์ `shop.buzlike` และ `well.buzlike` ด้วย แต่การมี repository ไม่ยืนยันสถานะพร้อมขาย โดย README ของ WELL ที่ตรวจระบุว่าเป็นแบบสำหรับพัฒนา จึงต้องตรวจสถานะแต่ละระบบก่อนเผยแพร่
- เดโมร้านค้าและระบบจองบางส่วนใช้เว็บไซต์ภายนอกตามที่ผู้ใช้เคยระบุ ต้องไม่อ้างเว็บไซต์เหล่านั้นเป็นผลิตภัณฑ์ที่เราเป็นเจ้าของ

ก่อน implement ให้จัดรายการระบบ ชื่อที่ลูกค้าเข้าใจ ผู้ใช้งานเป้าหมาย สถานะ และปุ่มที่ควรแสดงให้ครบก่อน ไม่สรุปยอดรวมจากเฉพาะรายการที่มีในส่วนผลิตภัณฑ์ปัจจุบัน การ์ดเต็มแถวในภาพจำลองเป็นการประเมินการเพิ่มระบบกฎหมายเท่านั้น ต้องพิจารณาความยาวหน้ารวมอีกครั้งเมื่อได้รายการทั้งหมด

## สิ่งที่ตรวจพบจากเว็บจริง

- หน้าแรกเป็นหน้าใช้งานผู้ช่วยกฎหมายโดยตรง มีช่องพิมพ์คำถาม เลือกหมวด และตัวอย่างสถานการณ์
- ผู้เยี่ยมชมเห็นโควตา “สิทธิ์วันนี้ 1/1 ครั้ง” ส่วนหน้าต่างเข้าสู่ระบบระบุฟรี 3 ครั้งต่อวัน
- การเข้าสู่ระบบเปิดเป็นหน้าต่างในหน้าเดิม มี LINE, Google และอีเมล OTP ให้เลือก ยังไม่ได้ทดสอบการยืนยันตัวตนจริง
- ไม่พบรายการราคาแพ็กเกจหรือขั้นตอนซื้อในหน้าสาธารณะที่ตรวจ จึงยังไม่มีหลักฐานพอให้ใส่ราคาหรือปุ่มซื้อบนเว็บหลัก
- ลิงก์ที่มองเห็นในหน้าหลักของระบบมีเพียงชื่อแบรนด์กลับหน้าระบบเอง ยังไม่มีทางกลับศูนย์รวมผลิตภัณฑ์ BUZLIKE
- ชื่อแบรนด์ที่ใช้งานจริงคือ “ดอกเตอร์ลอว์เยอร์” ควรคงไว้ แล้วเสริมว่าเป็นผลิตภัณฑ์ของ BUZLIKE SYSTEMS

ไม่ได้ส่งคำถามกฎหมาย สร้างบัญชี ขอ OTP หรือส่งต่อข้อมูลไป LINE การตรวจนี้ยังไม่ยืนยันคุณภาพคำตอบ ความถูกต้องของฐานกฎหมาย หรือความพร้อมของการเก็บเงิน

## การนำเสนอและเส้นทางลูกค้า

`หน้าแรก BUZLIKE → ผลิตภัณฑ์ของเรา → ดอกเตอร์ลอว์เยอร์ → เปิดผู้ช่วยกฎหมายในแท็บใหม่ → ถามคำถาม / เข้าสู่ระบบในผลิตภัณฑ์`

เนื้อหาการ์ดที่เสนอ:

- ชื่อ: **ดอกเตอร์ลอว์เยอร์**
- คำอธิบายหลัก: **ผู้ช่วยกฎหมาย AI สำหรับคำถามเบื้องต้น**
- รายละเอียด: พิมพ์คำถามหรือเลือกตัวอย่างสถานการณ์ เพื่อเริ่มค้นหาข้อมูลกฎหมายไทยเบื้องต้น ใช้งานผ่านเบราว์เซอร์
- จุดเด่น: คำถามกฎหมายไทย / ตัวอย่างสถานการณ์ / เริ่มถามแบบผู้เยี่ยมชม
- สถานะ: เปิดให้ทดลองใช้งาน — ไม่ระบุว่าเป็นแพ็กเกจพร้อมซื้อหรือโครงการนำร่องแบบเดียวกับ POS
- ปุ่มหลัก: **เปิดผู้ช่วยกฎหมาย** → `https://lawyer.buzlike.com/`, `target="_blank" rel="noopener"` พร้อมแจ้งว่าเปิดแท็บใหม่
- ปุ่มรอง: **สอบถามการใช้งาน** → `#contact` ของเว็บหลัก
- ข้อความกำกับสั้น: ข้อมูลกฎหมายเบื้องต้น ควรตรวจสอบกับทนายความก่อนตัดสินใจ

ไม่ใช้ราคาเริ่มต้นงานพัฒนา 15,000 บาทเป็นราคาของผลิตภัณฑ์นี้ ไม่เพิ่มสัญญาเชิงโฆษณาว่า AI ตอบถูกทั้งหมด และไม่ใส่ฟังก์ชันจัดการองค์กร/ตรวจสัญญาจากโค้ดอีกชุดก่อนตรวจว่ามีในระบบที่เปิดให้ใช้จริง

## วิธีรักษา layout เดิม

1. เพิ่ม `article` อีกตัวใน `.product-catalog-list` ใช้ anchor ใหม่ `#doctor-lawyer` โดยคง `#products` และ `#buzlike-pos`
2. ใช้โครง Grid และ breakpoint เดิม: คอมเป็นข้อความคู่ภาพ มือถือเรียงข้อความ ภาพ แล้วปุ่ม ไม่เปลี่ยนทั้งแคตตาล็อกเป็นสองคอลัมน์
3. แยกสีของการ์ดกฎหมายด้วย modifier เฉพาะตัว เช่น `.product-card--lawyer` ไม่แก้ selector กลางของ hero, header หรือการ์ด POS
4. รูปใช้ภาพหน้าจอจริง กำหนดพื้นที่สื่อไว้ล่วงหน้า และใช้ `object-fit: contain` เพื่อรักษาสัดส่วนภาพ ไม่ยืดภาพ 16:9 ให้เป็น 3:2
5. ความสูงข้อความให้ไหลตามเนื้อหา ไม่กำหนดความสูงการ์ดหรือซ่อนข้อความให้เท่ากัน การเพิ่มการ์ดย่อมเลื่อนส่วนถัดไปลง แต่ต้องไม่เปลี่ยนขนาดหรือตำแหน่งของ POS และ hero เดิม
6. ไม่ฝังระบบกฎหมายใน iframe เดโม และไม่เพิ่มโดเมนนี้เข้าเส้นทางเดโมของ `site-navigation.js`

## ผลการจำลอง

จำลองเพิ่มการ์ดใน DOM ของเบราว์เซอร์ชั่วคราว โดยใช้ภาพหน้าสาธารณะจริง ไม่มีการเขียนไฟล์เว็บหรือเปลี่ยนเซิร์ฟเวอร์

ผ่าน **18 จุดตรวจ** ที่ 320, 390, 768, 901, 1024 และ 1440px: การ์ด POS เดิมมีขนาดและตำแหน่งเดิม การ์ดผลิตภัณฑ์สองตัวไม่ทับกัน ไม่ล้นแนวนอน และข้อความ/ภาพ/ปุ่มในตัวใหม่ไม่ชนกัน เปิดตรวจภาพจำลองที่ 390 และ 1440px แล้ว

หลักฐานอยู่ใน `output/playwright/lawyer-product-plan/`: `layout.txt`, `lawyer-desktop.png`, `lawyer-mobile.png`, `proposal-390.png`, `proposal-1440.png` เป็นภาพจำลองสำหรับประเมิน layout ไม่ใช่หน้าที่เผยแพร่แล้ว

## ลำดับ implement

1. เพิ่มการ์ดบนเว็บหลักและภาพ WebP พร้อม cache key ใหม่ โดยไม่แตะ hero หรือเมนูอื่น
2. เพิ่มข้อความผลิตภัณฑ์ของ BUZLIKE และลิงก์กลับ `https://buzlike.com/#products` ในระบบกฎหมาย หลังตรวจชุดไฟล์ที่ใช้งานจริงก่อนแก้
3. ตรวจมือถือ/คอม ลิงก์ตรงทั้งเก่าและใหม่ การเปิดแท็บใหม่ ปุ่มกลับจากเดโมทั้ง 6 ตัว ตำแหน่งเลื่อนและข้อมูลแบบประเมินเดิม ก่อนเผยแพร่เฉพาะไฟล์ที่เปลี่ยน

การเชื่อมรอบแรกใช้ลิงก์ระหว่างผลิตภัณฑ์เท่านั้น จึงไม่ต้องแก้ฐานข้อมูล บัญชีสมาชิก SSO หรือส่งเนื้อหาคำถามกฎหมายกลับเว็บหลัก หากต้องการบัญชีเดียวใช้ทุกระบบ ควรวางแผนเป็นงานแยกภายหลัง

ข้อสังเกตสำหรับผู้ implement: ใน repository ระบบกฎหมายมีทั้ง `frontend/index.html` และแอปใน `web/` แต่เว็บสาธารณะที่ตรวจมีรูปแบบตรงกับหน้า `frontend/index.html` ไม่ใช่เส้นทาง Next.js ที่ redirect ไป `/chat` จึงต้องยืนยันต้นทางที่ deploy อยู่ก่อนแก้ลิงก์กลับ ห้ามนำอีกแอปไปแทนระบบจริงเพียงเพื่อเพิ่มการ์ดผลิตภัณฑ์
