# แผนเชื่อม BUZLIKE SYSTEMS → BUZLIKE POS

วันที่ตรวจ: 14 พฤศจิกายน 2026 · สถานะ: รอบ 1 เผยแพร่และตรวจแล้ว ดู [ผลส่งมอบรอบ 1](POS_PRODUCT_LINK_DELIVERY_2026-11-14.md) ส่วนรอบ 2 ยังเป็นแผน

## ข้อเสนอหลัก

ให้ BUZLIKE SYSTEMS เป็นเว็บหลักของแบรนด์ มีทางเลือกที่ชัดเจนสองแบบ: **ใช้ผลิตภัณฑ์ของเรา** และ **จ้างพัฒนาระบบสำหรับธุรกิจ** โดยนำ BUZLIKE POS มาแสดงเป็นผลิตภัณฑ์แยกจากเดโมและเครื่องประเมินค่าพัฒนา

เริ่มจากการเชื่อมหน้าเว็บและเส้นทางลูกค้า ไม่ต้องรวมฐานข้อมูล บัญชี หรือระบบชำระเงินระหว่างสองเว็บในงานนี้

## เส้นทางที่ลูกค้าควรเจอ

```text
BUZLIKE SYSTEMS — buzlike.com
  ├─ อยากใช้ POS → บล็อก BUZLIKE POS → หน้าผลิตภัณฑ์ POS
  │                                      ├─ ผู้สนใจใหม่ → ลงทะเบียนรอ
  │                                      └─ ลูกค้าเดิม → เข้าสู่ระบบร้าน
  └─ อยากได้ระบบตามโจทย์ → ตัวอย่างระบบ → ประเมินงบ → ติดต่อ
```

### 1. ทางเข้าบนเว็บหลัก

- เพิ่มเมนู **“ระบบ POS”** บน desktop และ mobile ชี้ไป `#buzlike-pos` ภายในหน้า ไม่ทำ dropdown สำหรับผลิตภัณฑ์เดียว
- เพิ่มข้อความลิงก์สั้นใต้กลุ่มปุ่ม Hero: **“มีร้านอยู่แล้ว? รู้จัก BUZLIKE POS →”** ชี้ไปบล็อกเดียวกัน โดยไม่เพิ่มปุ่มหลักขนาดใหญ่อีกปุ่ม
- วางบล็อก POS หลัง Hero ก่อนส่วนตัวอย่างระบบเดิม ให้พบได้เร็วและมี URL `https://buzlike.com/#buzlike-pos` สำหรับกลับจาก POS
- ส่วนตัวอย่างและแบบประเมินเดิมยังเข้าถึงตรงได้ด้วย hash เดิม; ปรับชื่อส่วนราคาเป็น **“ค่าพัฒนาระบบ”** เพื่อสื่อว่าราคาเริ่ม 15,000 บาทเป็นคนละบริการกับ POS

### 2. เนื้อหาและหน้าตาบล็อก POS

ใช้บล็อกแนะนำผลิตภัณฑ์ที่มีน้ำหนักชัดเจนหนึ่งบล็อก ไม่ทำเป็นการ์ดเดโมเพิ่มในกลุ่ม “ตัวอย่างเพิ่มเติม”

| องค์ประกอบ | ข้อความ/พฤติกรรมที่เสนอ |
|---|---|
| ชื่อ | BUZLIKE POS |
| ประเภท | ผลิตภัณฑ์ของ BUZLIKE SYSTEMS |
| หัวเรื่อง | ระบบขายหน้าร้าน เชื่อมงานร้านไว้ในที่เดียว |
| คำอธิบาย | สำหรับคาเฟ่ ร้านอาหาร และร้านค้าปลีก ตั้งแต่งานขายและยอดขาย ไปจนถึงจอครัวและวัตถุดิบตามแพ็กเกจ |
| ภาพ | ภาพหน้าจอ POS จากร้านทดสอบที่ใช้อยู่บนเว็บผลิตภัณฑ์ ระบุว่าเป็นข้อมูลทดสอบและตรวจให้ไม่มีข้อมูลลูกค้าจริง |
| สถานะ | อยู่ระหว่างเปิดโครงการนำร่อง · ผู้สนใจลงทะเบียนรอได้ |
| ปุ่มหลัก | “ดูรายละเอียด BUZLIKE POS ↗” → `https://pos.buzlike.com/` |
| ปุ่มรอง | “ลงทะเบียนรอเปิดบริการ ↗” → `https://pos.buzlike.com/pilot/waitlist` |
| ลิงก์สำหรับลูกค้าเดิม | “มีบัญชีร้านแล้ว? เข้าสู่ระบบ ↗” → `https://pos.buzlike.com/login` |
| ราคา | “ดูแพ็กเกจและเงื่อนไขบนเว็บ POS” → `https://pos.buzlike.com/#pricing` |

ใช้พื้นและตัวอักษรจากเว็บหลัก ส่วนรายละเอียดสีส้มให้เชื่อมกับภาพลักษณ์ POS ปุ่มหลักต้องเด่นกว่า action อื่น ภาพมีพื้นที่สำรองตามสัดส่วนเพื่อไม่ให้ layout กระโดด มือถือเรียงข้อความ → ภาพ → ปุ่ม ปุ่มกดได้อย่างน้อย 44px และไม่ต้อง hover เพื่ออ่านข้อความ

### 3. แยกเดโมเดิมออกจากผลิตภัณฑ์

- เปลี่ยนชื่อคำเรียกบนการ์ดให้ชัดว่า **“ตัวอย่างหน้าร้านและจอครัว”** และคงคำว่า “ข้อมูลจำลอง”
- เพิ่มข้อความ **“ต้องการใช้งานกับร้านของคุณ? ดู BUZLIKE POS”** เชื่อมไปผลิตภัณฑ์; ไม่แทนที่ปุ่มทดลองเดโมหรือเอาเดโมออก
- ในหน้าเดโม POS เพิ่มทางออกไปผลิตภัณฑ์โดยระบุว่าเปิดเว็บไซต์ POS แยกต่างหาก ใช้ anchor `target="_blank" rel="noopener"` เพื่อไม่เปิดระบบจริงซ้อนใน iframe ของเดโม
- ไม่ส่งตะกร้า ออเดอร์ หรือข้อมูลเดโมไปสร้างร้านใน POS จริง

### 4. การเปิดและกลับระหว่างเว็บ

- ลิงก์จากเว็บหลักไป POS เปิดแท็บใหม่ พร้อมสัญลักษณ์ ↗ และ accessible label ระบุเปิดแท็บใหม่ เพื่อคงตำแหน่ง scroll และแบบประเมินของเว็บหลักไว้ในแท็บเดิม
- ไม่เพิ่ม subdomain POS เข้า allowlist ของ `site-navigation.js`: กลไก iframe ปัจจุบันใช้สำหรับเดโม same-origin เท่านั้น
- บน POS เปลี่ยนเมนู “เกี่ยวกับเรา” เป็น “BUZLIKE SYSTEMS” → `https://buzlike.com/#buzlike-pos` และคงโลโก้ BUZLIKE POS ชี้หน้าแรกของ POS ตามเดิม
- การกดลิงก์กลับเว็บหลักจาก POS เป็นการนำทางข้ามเว็บตามปกติ ลิงก์ hash ช่วยกลับมาบล็อก POS ได้ แต่ไม่สัญญาว่าจะคืน pixel scroll ของอีกแท็บ; การสลับกลับแท็บเว็บหลักเดิมจะคงตำแหน่งเดิม
- ไม่ต้องแชร์ login/session ข้าม subdomain; main site ไม่ต้องเข้าถึงบัญชีร้านเพื่อแสดงปุ่ม login

## ลำดับ implement

| รอบ | ขอบเขต | ผลลัพธ์ที่ตรวจรับได้ |
|---|---|---|
| 1 — เริ่มก่อน | เมนู POS + ลิงก์ Hero + บล็อกผลิตภัณฑ์ + ชื่อค่าพัฒนา | คนเข้าเว็บหลักพบ POS และแยกการลงทะเบียนรอออกจากการจ้างพัฒนาได้; ปุ่มไปปลายทางถูกต้อง |
| 2 | แก้คำเรียกเดโมและเพิ่มปุ่มไป POS ในเดโม + เปลี่ยนชื่อเมนูกลับเว็บหลักฝั่ง POS | คนทดลองเดโมมีทางไปผลิตภัณฑ์จริง และกลับเว็บหลักได้อย่างคาดเดาได้ |
| 3 | ตรวจทั้งเส้นทาง desktop/mobile, keyboard และ navigation regression แล้วเผยแพร่ | เว็บหลัก/เดโมเดิมไม่เสีย กลับจุดเดิมได้ และไม่เปิด POS ใน iframe |
| หลังเปิดบริการทั่วไป | ปรับข้อความสถานะ/ปุ่มสมัครให้ตรง release policy ที่เปิดจริง | ผู้สมัครใหม่เข้าเส้นทางสมัครและตั้งร้านที่เปิดแล้ว โดยไม่ใช้ข้อความนำร่องค้าง |

ไม่เพิ่มหน้า product hub, shared database, SSO หรือระบบรับชำระใหม่ในสามรอบนี้ หากมีผลิตภัณฑ์ที่เปิดใช้งานเพิ่มค่อยขยายเมนู “ระบบ POS” เป็น “ผลิตภัณฑ์”

หากต้องการวัดผลภายหลัง ให้กำหนด source/UTM แยกตำแหน่ง header, product block และ demo ก่อน แต่จะสรุปจำนวนสมัครจากเว็บหลักได้ก็ต่อเมื่อฝั่ง POS รับและเก็บ attribution จริง การติด UTM อย่างเดียวไม่ยืนยัน conversion

## จุดที่ต้องแก้เมื่อเริ่มงาน

- เว็บหลัก: `public/index.html`, style ส่วนหน้าแรกใน `public/previews/living-systems/hero.css`; sync หน้า root ผ่านกระบวนการ generate เดิม ไม่แก้ generated copy ให้ต่างกัน
- หากเปลี่ยนข้อความ metadata ให้แก้ที่ `src/PageMetadata.json` แล้วใช้ `scripts/generate_page_metadata.py`
- ลิงก์ผลิตภัณฑ์ควรมีแหล่งกำหนดเดียวสำหรับตำแหน่งที่ใช้ซ้ำ เช่น public product configuration โดยไม่เก็บ secret และไม่ผูกเข้ารายการเดโม
- เดโม: ตรวจตำแหน่งแสดง conversion actions ใน `public/assets/app.js` ก่อนเพิ่มปุ่มเฉพาะ POS; ไม่ใช้การเปลี่ยนข้อความรวมทุกระบบ
- POS: `src/components/marketing-header.tsx` และ footer ใน `src/app/page.tsx`
- ไม่เปลี่ยน release policy, trial, ราคาขาย หรือฐานข้อมูลของ POS เพื่อให้ตรงข้อความการตลาด; ใช้สถานะผลิตภัณฑ์เป็นตัวกำหนดข้อความ

## เกณฑ์ทดสอบก่อนเผยแพร่

1. หน้า desktop และมือถือ 390px เห็นทางเข้า POS ในเมนู และบล็อก POS ไม่ล้นจอ ไม่มีตัวหนังสือทับภาพหรือปุ่ม
2. ปุ่มรายละเอียด → หน้า POS, ลงทะเบียนรอ → waitlist, ลูกค้าเดิม → login, ราคา → pricing ถูกต้อง ผ่าน HTTPS และไม่เข้าหน้าเครื่องประเมินค่าพัฒนา
3. เว็บหลักบอกว่ายังลงทะเบียนรอ ไม่อ้างเปิดใช้ทันที/ทดลองใช้ฟรีทั่วไป; ไม่ตีความการรอเป็นได้รับสิทธิ์นำร่อง
4. กด POS แล้วสลับกลับแท็บเดิม: scroll, expanded details และข้อมูลแบบประเมินยังอยู่; ไม่สร้าง iframe ข้าม subdomain
5. เดโมทุกตัว: กลับหน้าแรกด้วยปุ่มเว็บและ Browser Back, เปิดเพิ่ม 4 ระบบแล้ว refresh เดโมก่อนกลับ ต้องคงพฤติกรรมที่แก้ไว้
6. ลิงก์กลับจาก POS ถึง `#buzlike-pos`; โลโก้ POS และ login ยังทำงานตามบทบาทเดิม
7. Tab/Enter ใช้เมนูและทุกปุ่มได้ มี focus มองเห็น; ระบุเปิดแท็บใหม่และมี alt ของภาพที่สื่อความหมาย
8. ไม่สร้างผู้สมัคร/ร้าน/ออเดอร์จริงในการตรวจลิงก์ หากจะทดสอบสมัครจนจบให้แยกเป็น QA ของ POS โดยเฉพาะ

## หมายเหตุวิธีวิเคราะห์

อ่านแนวทาง UI/UX Pro Max เรื่อง predictable navigation, accessibility และขนาด touch target ประกอบการตัดสินใจ การค้นรูปแบบ landing เฉพาะไม่พบรายการที่ตรงหลังปรับคำค้น จึงใช้โครงสร้างเว็บจริงและเส้นทางลูกค้าเป็นหลัก ไม่ถือว่ามี template จากฐาน skill ที่ยืนยันแล้ว
