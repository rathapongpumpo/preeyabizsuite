# POS print and mobile CTA — 2026-11-02

## Changes

- POS receipt has a dedicated print surface; app navigation, modal frame/buttons and conversion bar do not print.
- Printable width 72 mm plus 4 mm margins on each side gives an 80 mm sheet. Page length is measured from the actual receipt rather than fixed to Letter/A4.
- Print surface is created on the print button or browser `beforeprint`, then removed on `afterprint` so subsequent document printing is unaffected.
- Receipt retains actual order/items/totals; removes the fake tax ID and explicitly labels the simulated payment. The order toast no longer claims a receipt was already printed.
- Conversion bars use normal document flow at <=768 px, after application content. They are hidden while a modal is open at all sizes. Toggle has a 44 px target and expanded state.
- Removed obsolete mobile space reserved for the floating bar in WMS/POS. Cache versions and static/PHP entrypoints synchronized.
